# Four values

Self-taught, community-raised. I care about four things and I can show my work on all four. None
of them is a slogan; each has an artifact you can go and look at.

## User ease is a correctness property

NSGEM's stated end goal was to "increase data credibility" and to be "easy to use"
([navy.mil](https://www.navy.mil/Press-Office/News-Stories/display-news/Article/2265327/from-the-shore-navy-installations-take-energy-initiatives-to-the-next-level/)).
The Energy Biggest Loser competition was scored on it, and a culinary specialist was turning off
monitors because the tool made the stakes legible to him. If the person doing the work will not
use it, the number does not matter.

## Correctness means the ledger closes

I spent six hours walking an engineer through commission-split tests, because thirds of a cent do
not divide and someone has to own the remainder. Today I write harnesses where reverting only the
bound arithmetic makes six of thirteen checks fail on purpose — a check that is designed to fail
is a check you can trust when it passes.

## Client joy

Adoption is the deliverable. I have watched a tool with all the right features sit at 23% and a
humbler one reach 90% because someone did the change management. I build for the second number.
The features were not the difference; the handoff was.

## Environmental sustainability

62,000 billing statements mapped to facility-level usage across every Navy installation, in
multiple time zones, feeding a competition that reduced actual kilowatt-hours. The current record
is 1,188 days of solar production against weather, with snow separated from soiling, published
alongside what was excluded and what still narrows the population — see
[le.gume-energy](/work/le-gume-energy).

## Why these four together

They are not independent. A number that closes but cannot be read will be worked around; a system
that is pleasant but wrong is pleasant for less time; a tool nobody adopts changes nothing; and a
measurement that cannot say what it excluded is not a measurement. The common shape is the one in
[checkable claims](/ideas/checkable-claims): the answer stays valid only while the missing part
stays visible.
